# Showreel 高清重编码设计

## 目标

替换当前官网 Showreel 视频，改善全屏播放时的模糊问题，同时保持现有页面结构、封面和播放交互不变。

## 已确认根因

- 原片：1920×1080，25 fps，H.264 Main，视频码率约 9.85 Mbps。
- 当前上线版：1920×1080，25 fps，H.264 Baseline，视频码率约 3.48 Mbps。
- 当前封面为 3840×2160，不是模糊来源。
- 清晰度下降来自上线视频的低码率重编码。

## 实施方案

从原始 `0625_BC_CG Showreel.m4v` 重新编码：

- 分辨率保持 1920×1080。
- 帧率保持原片 25 fps。
- 视频目标码率控制在 5–5.5 Mbps。
- 音频使用 AAC 128 Kbps。
- 像素格式使用 yuv420p，保证主流浏览器兼容。
- 启用 faststart，便于网页渐进播放。
- 输出文件替换 `assets/videos/showreel.mp4`，不修改页面数据或 URL。

优先尝试硬件 H.264 编码；若编码器无法稳定满足质量或兼容性要求，则使用当前环境中可用的兼容 H.264 编码器，仍遵守相同的码率与文件大小约束。

## 验收标准

- 输出为可正常解码的 1920×1080、25 fps H.264 MP4。
- 视频平均码率不低于 5 Mbps，且不高于 5.5 Mbps 的目标范围。
- 文件必须小于 GitHub 单文件 100 MB 限制，并以 85–95 MB 为目标。
- 本地浏览器能够读取视频元数据并播放。
- 网站全部自动化测试继续通过。
- 部署后正式 URL 返回成功，线上浏览器能够读取 Showreel 视频元数据。

## 风险与处理

- 码率与最终大小会因编码器的码率控制略有波动；若超过 100 MB，则降低目标码率后重新编码。
- GitHub Pages 不提供自适应码率，本次只改善单一 1080p 文件的清晰度，不引入视频 CDN 或多分辨率流。
